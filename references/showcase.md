# 阶段 3：可交互展示页

## 核心思路：页面只读 manifest

展示页与具体对象无关。Python 侧把零件数据序列化进
`<script id="parts-data" type="application/json">{"parts":[...]}</script>`，
前端 `JSON.parse(document.getElementById("parts-data").textContent)`。
换对象时只换这份 JSON 与文案，三维部分几乎不动。

```json
{
  "model": "dgx_h100",
  "unit": "mm",
  "up": "+Z",
  "front": "-Y",
  "envelopeCadMm": [482.3, 897.1, 356.0],
  "parts": [
    {
      "id": "bezel",
      "label": "前挡板",
      "color": "#5d6b78",
      "glb": "bezel.glb",
      "explodeCadMm": [0.0, -650.0, 0.0],
      "explodeGlb": [0.0, 0.0, 0.65],
      "sizeCadMm": [482.3, 9.0, 356.0],
      "bboxGlb": [[-0.2411, 0, 0.4425], [0.2411, 0.356, 0.4515]],
      "triangles": 137070,
      "layered": false,
      "mb": 4.88
    }
  ]
}
```

字段职责：

| 字段 | 谁用 | 要求 |
|---|---|---|
| `id` | 拾取、选择状态、检查脚本 | 唯一、稳定，别用中文 |
| `label` | 零件树与气泡 | 中文，可在列表里加数量，如「H100 模组 ×8」 |
| `color` | 材质基色 | 与实物尽量接近，深浅拉开层次 |
| `glb` | 加载 | 相对 `parts/` 的路径 |
| `explodeCadMm` | 分解位移，CAD 坐标，便于对照图纸 | 与 `explodeGlb` 必须一致 |
| `explodeGlb` | 前端直接用 | `(x, z, −y)/1000` |
| `bboxGlb` | **取景、气泡、剖切诊断全靠它** | 必须从实际 GLB 量，不能估算 |
| `sizeCadMm` | 面板上显示尺寸 | 由 bbox 反算校验 |
| `triangles` | 指标卡 | 实测 |
| `layered` | 是否上层件（气泡朝向用） | 布尔 |

`bboxGlb` 是唯一不能省的字段：前端拿它算取景的角点、挂气泡、做剖切诊断。
少一个或写错，表现为「模型跑到画面外」或「点不中」。

## 取景解算（这是「模型只占半屏」的解药）

错误做法：把 14 个零件的包围盒并成一个，取 8 个角。分解态下这 8 个角里有 4 个现实中不存在
（既没有零件也没有任何东西），为照顾它们只能退远。

正确做法：

1. 逐件取**自己的 8 个真实角点**，加当前分解位移
2. 逐轴解 `f(a) = max_i(|lat_i − a| / tan(halfFov) + depth_i)` —— 这是凸函数，三分搜索
3. 两轴取较大距离后，**按最终距离重解一次**（加权切比雪夫中心二分），消除非主导轴偏移
4. 乘以 `FIT_MARGIN = 1.10`（1.03 时标注气泡会被切）

效果：同一台机器占屏从 55% 提到 88–90%。

约束：**选中零件时不推近**。推近到单件必然使整机投影溢出，几何无解。焦点靠材质变化表达。

## 材质与焦点

- `GHOST_OPACITY = 0.17`。0.09 时其余零件几乎看不见，整机像只剩一层；0.17 能一眼分出
  「这层是主体，其余是衬底」，又不抢戏。
- 全部材质 `side: DoubleSide`，否则薄板背面消失。
- 加跟随相机的 headlight，否则暗面全黑。
- 顶视图别取纯 `(0,1,0)`，`lookAt` 会退化，给一点 X 分量。

## 剖切：四条规则

1. **平面常驻，只改常数**。`clippingPlanes` 数组一改长度就重编译 shader，
   几十个材质会明显卡顿。
2. **关闭时把常数写到 `1e3`**。不要写「包围盒外 5%」—— 那个距离在分解态下会被追上，
   上层件和前端件直接整片消失，而且**前端判据认为「没剖」，检查脚本查不出来**。
3. **每次分解变化都无条件重算常数**，取当前分解态的未裁剪包围盒。取点必须是未裁剪的，
   否则平面自己往下追、越剖越窄。
4. **取景过滤被裁掉的角点**。剖完断面只占半屏就是漏了这步。过滤后为空要退回整体，
   否则取景函数拿空数组算出 `Infinity`。

配合一个**诊断接口**：`stageApi.clipReport()` 返回每件零件 8 个世界角点到三条平面的最小有符号距离。
检查脚本在「分解 100% + 未剖切」时断言全部为正。这是唯一能抓住第 2 条坑的办法。

## 单文件内嵌

`file://` 下 fetch 与 ES module 都被 CORS 拦，所以：

1. GLB → gzip（约 22%）→ base64 → 塞进 `<script type="text/plain">`
2. 运行时 `atob` → `DecompressionStream("gzip")` → `GLTFLoader.parse`
3. three.js 前端用 esbuild 打成 IIFE（`--format=iife --global-name=XXX`，走
   `three/addons/*` 路径 + `NODE_PATH`）

体积参考：16.7 MB 整机 GLB → 7 MB 单文件页面；逐件 14 个 GLB → 6.3 MB 展示页。
首次打开约 5 秒（要现场解压 57 万面）。

## 右栏空间预算

零件树 + 开关 + 剖切滑块很容易超出可视高度，而 `overflow` 一裁，观众就不知道下面还有控件。

- 先量：无头浏览器 dump 每个 section 与子项高度，算「内容高 / 可视高」
- 只能压间距，不能删内容：`tree-item` padding 7→4、`gap` 4→2、`toggles gap` 9→6、
  `.pane section+section` 16→12、`h2 margin` 11→9
- **14 件就能把右栏填到零余量**。超过 20 件必须先做分组折叠（manifest 加 `group`）、
  虚拟滚动，否则怎么压都不够

## 产物画廊与放大

- 两列，单张 528 px。**试过三列（348 px），零件特写里那件东西只剩一百多像素，图多了反而看不清**
- 别用 `grid-column: span 2` 做首图：同行卡片被 stretch 拉到同高，图在上、说明在底、中间一大片空白。
  要首图大就拆成两个网格容器
- 图片统一 `aspect-ratio: 3/2` + `object-fit: contain`，竖版图纸居中不切内容
- 点开放大：卡片图包成 `<button class="card-img">`，Esc / 点空白 / 关闭按钮都能关，
  打开时锁 body 滚动，关闭后焦点还给原卡片
- **坑**：事件绑定选择器要写全 `.gallery-lg .card, .gallery .card`。只写 `.gallery` 时
  大图组点不动，而且检查脚本只会报「没打开」，不指位置
