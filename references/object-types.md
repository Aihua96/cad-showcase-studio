# 阶段 0：对象类型适配

同一套流水线，四种对象的差别集中在四件事：**分解语义、精度档、面数预算、构件树结构**。

## 对照表

| 对象 | 分解语义 | 精度档 | 面数预算 | 构件数 | 真正好用的功能 |
|---|---|---|---|---|---|
| 机架设备（服务器/交换机/存储） | 沿装配轴平移，与维护手册顺序一致 | 外形精确、内部重建 | 50 万 | 10–20 | 分解 + 点选 + 后视图 |
| 机械结构 | 沿配合面/螺栓方向分离 | 可精确（有图纸时） | 60 万 | 10–80 | 分解 + 剖面 |
| 建筑 | 按楼层自下而上；或按系统（结构/围护/机电） | 精确（图纸齐全） | 30 万 | 50–300 | **剖切** + 分层 |
| 桥梁 | 按施工逆序：桩基→承台→墩身→支座→主梁→桥面→拉索 | 精确 | 80 万 | 50–500 | **剖切** + 施工顺序 |

**建筑和桥梁的「爆炸图」在专业语境里不常用**，叫「分层」或「施工顺序」更自然。
真正有说服力的是剖面 —— 建筑剖面图、桥梁横向布置图本来就是这两个专业的核心表达，
剖切功能迁过去收益最大。

## 尺度切换清单

对象从 0.9 m 变成 90 m 或 900 m 时，下面这些**全部要重设**，漏一个就会表现成「坏了」：

- `cadgen` 调用里的裸数字（统一走 `MM`，不要混用米和毫米）
- 相机 `near` / `far`（差 1000 倍会出 z-fighting 或整片裁剪）
- 地面网格尺寸与分段数
- 阴影偏移与阴影相机范围
- 标注线宽、字体大小（在屏幕空间恒定，所以要按投影尺寸调）
- 分解位移量级（桥梁的「抽出」可能是几十米）
- 探针里的像素阈值

## 构件树结构

14 件以内可以平铺。超过 20 件必须改结构：

```json
{ "group": "上部结构", "id": "girder_03", "label": "第 3 跨主梁" }
```

前端做两级折叠（组 → 件），并只渲染展开的组。右栏高度是硬约束：
本项目 14 件已经把 1500×1000 下的右栏填到 820/820 px，零余量。

命名建议：`<部位>_<序号>`，如 `pier_02`、`girder_03`、`cable_12`。
序号用两位数，排序才稳定。

## 图纸输入四档与转换路径

`cadgen` **只有 `read_step`，没有 DXF/DWG 导入**，所以图纸永远要先转成几何。

| 图纸形态 | 能拿到什么 | 转换路径 |
|---|---|---|
| DWG / DXF（有图层） | 精确轮廓、标高、标注 | `ezdxf` 或 FreeCAD 读轮廓 → 挤出/旋转成实体 → 写几何脚本 |
| 矢量 PDF（有文字层） | 尺寸文字及其坐标（`pypdfium2`） | 抽尺寸表 → 写几何脚本 |
| 扫描图 / 高清照片 | 只有像素 | 双特征互校标定 → 反推（见 `geometry.md`） |
| 手持照片 | 只有比例关系 | 只能「形似」，不出工程精度 |

判断 PDF 有没有文字层，一行就能验：

```python
import pypdfium2 as pdfium
page = pdfium.PdfDocument("x.pdf")[0]
print(len(list(page.get_textpage().get_text_range())))  # 0 说明是扫描件
```

图纸给的是**尺寸**，不是**几何**。2D 轮廓到 3D 实体这一步仍然要写代码，
只是从「猜尺寸」变成「照尺寸写」。这一步的工时占比，大约从「大头」降到「三分之一」。

## 先做一个最小可验证对象

在完整对象之前，先跑一个**一段桁架 / 一个桥墩 / 一层建筑**，验证四件事：

1. 尺度切换（相机与网格参数）
2. 分组零件树（折叠是否够用）
3. 分解语义（这个对象的「拆开」到底怎么讲）
4. 影片模板化（6 幕是否够用）

这四件事在完整对象上会同时爆发，在小对象上可以逐个排查。

## 合规提醒

甲方图纸、保密工程、在役设备的内部构造，**不能公网上线**。
公开发布前必须确认授权；不确定时做概念化重构：去掉真实尺寸、去掉专有构造、
只保留受力与空间关系的示意。这一条在建筑与桥梁项目上比机架设备更常踩。
